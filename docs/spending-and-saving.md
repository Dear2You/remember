# 消费预算与存钱（v2.32）

全账本月消费上限与月存钱计划存入 `moneyPlans`，以自然月为单位。`repeat` 从所选月份向后沿用，新的月度设置覆盖此前规则，不回写历史月份；停用保存 0 值规则，防止旧计划重新出现。原有账本／分类预算保留，各口径不相加。

支出按 `out` 汇总，信用卡消费计一次，转账、还款本金与出差垫付／报销不计个人消费；关联手续费是普通 out 支出，计入消费。编辑账单先扣除原记录再预览新金额；新增或增加支出超限时二次核对，取消不写入。已经花出去的钱仍允许如实记录。AI 直接记录的支出在结果中注明超限。

主要存钱账户默认识别现有建行卡，可手动更换。`savingGoals` 每个目标关联一个资产账户，同一账户不能重复关联；目标进度来自完整账户余额。月存钱进度合并主要存钱账户与所有目标账户后去重，汇总其当月净流入；目标间转账相互抵消，期初余额不计本月新存的钱。删除目标保留账户和流水；主要存钱账户的独立设置保留。所有新数据随原完整 JSON／云备份保存与恢复。

预算起步参考根据用户提供的联培、月薪约 6000、企业提供午饭设计：消费 2000、存钱 3000、机动 1000。它是可编辑的表单建议，必须在应用中保存才启用，方案按企业提供宿舍及午饭、主要步行通勤的场景提供，仍保留其他开销。优先依据实际到手收入、完整月份花销调整。参考 [Consumer.gov：Making a Budget](https://consumer.gov/your-money/making-budget) 关于按实际收支制定预算、将存钱纳入计划的方法；金额是本应用的情景建议，并非来源推荐。

主要验收：跨账本／跨月、闰月日额度、账单编辑和取消、信用卡与报销去重、存取修改删除、备份恢复与非法数据拒绝、存储失败原子回滚、隐藏金额及移动端布局。

「消费节奏」取 `Store.budgetPace`。每天的参照额按「月上限 × 当月第几天 ÷ 本月总天数」四舍五入至分，累计个人支出按发生日计入。整月视图可包含预先登记的未来账单，本月曲线只到当天。助手的消费节奏问答和图面使用同一组数据。


专项额度与白条

对银行或白条账单时，在「资产」选择账户，信用账户从「总负债 → 明细」进入。选账单的截止日并输入当日实际余额或欠款。核对从期初余额累计所有账本中截至当天的流水，包含转入、转出、还款和手续费；差额只用于核对。查找一笔消费时，可在「账单 → 筛选账单」按单笔金额或范围筛选。转账按到账本金匹配，关联手续费按单独的一笔支出匹配。

`moneyPlans.focusLimits` 包含 shopping、delivery、drinks 三项可选上限，随月计划沿用，归属全部账本。购物依据分类，外卖／饮品依据分类和餐饮备注；每笔只归一组，饮品优先于备注中的外卖，不把买菜归入外卖。额度不是额外消费额度。建议总消费 2000，其中购物 500、外卖 200、奶茶 100，其他参考做饭吃饭 700、交通 100、其他 400；保存建议后补充买菜做饭、奶茶饮品分类。已有计划不自动覆盖。

白条是独立负债账户。建账只填未逐笔记过的历史欠款；购买当日记 out 增加负债并占用预算，还款是资产向负债转账。预算页分账户展示本月个人消费、还款、出差垫付（另列）和当前全部欠款，首页给出信用消费与待还摘要。待还不代表平台本期应还。App 不读取京东账户或代扣款。

转账手续费的数据约定

转账 `amountMinor` 始终为实际到账 / 还款本金，`feeMinor` 为手续费，`feeMode` 为 extra（额外扣除）或 deduct（金额内扣除）。编辑时还原用户输入额。转出总额 = 本金 + 手续费：本金按 transfer 改双方余额，手续费作为一笔关联 out 扣同一转出账户，`transferFeeFor` 指向父转账。同一事务中增改删费用，写入失败整体回滚；费用明细点击跳回父转账，禁止孤立改删。费用清零或转账改为普通收支时移除子费用。导入校验父子数量、日期、账户、账本、金额，拒绝孤立费用；旧无手续费记录仍兼容。CSV 将手续费导出为单独支出行。

键盘适配

Android 11+ 明确关闭 decor 自动 inset 处理，在 FrameLayout 中取系统栏、刘海及 IME 高度，底边取最大值，不相加。消费 insets 前同时处理 IME，避免旧实现仅留系统栏导致键盘覆盖 WebView。旧 Android 继续用 adjustResize / fitsSystemWindows。前端按 VisualViewport 或原生键盘状态收起底栏、适配弹层高度，并滚动正在编辑的表单字段，不重建输入或打断中文组合输入。参考 [Android edge-to-edge](https://developer.android.com/develop/ui/views/layout/edge-to-edge) 与 [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)。桌面自动化模拟键盘区域通过，尚未在用户小米手机上实测。
